# 标签系统规范

## 📋 概述

本规范定义了Obsidian vault中使用的标签系统标准，旨在建立统一、可扩展的标签体系，提升知识检索效率和组织一致性。

## 🎯 设计原则

1. **层级清晰**: 使用斜杠(`/`)创建层级关系
2. **语义明确**: 标签名应准确反映内容主题
3. **适度抽象**: 避免过度具体或过度抽象
4. **可扩展性**: 系统应能容纳新主题和分类
5. **一致性**: 相同概念使用相同标签

## 🏷️ 标签层级结构

### 一级分类：领域 (Domain)

#### 1. 领域/工作 (work/)
工作相关的内容，包括岗位职责、绩效考核、项目管理等。

**二级分类**:
- `work/岗位` - 岗位职责、职位描述
- `work/绩效` - 绩效考核、评估、复盘
- `work/营销` - 营销策划、活动执行
- `work/管理` - 管理规范、流程、制度
- `work/团队` - 团队管理、协作、建设
- `work/项目` - 项目管理、执行、跟踪

**常用标签**:
- `work/岗位/企划经理`
- `work/绩效/季度复盘`
- `work/营销/节日营销`
- `work/管理/管理迭代3.0`
- `work/团队/团队管理`

#### 2. 领域/个人 (personal/)
个人发展、学习成长相关内容。

**二级分类**:
- `personal/AI` - AI技术、工具、应用
- `personal/学习` - 学习笔记、知识积累
- `personal/成长` - 个人发展、技能提升
- `personal/读书` - 读书笔记、书评
- `personal/健康` - 健康管理、生活品质

**常用标签**:
- `personal/AI/工具`
- `personal/学习/知识管理`
- `personal/成长/技能提升`
- `personal/读书/读书笔记`

#### 3. 领域/技术 (tech/)
专业技术、工具、系统相关内容。

**二级分类**:
- `tech/Obsidian` - Obsidian使用、插件、技巧
- `tech/编程` - 编程语言、开发工具
- `tech/系统` - 系统架构、技术方案
- `tech/数据` - 数据分析、处理

**常用标签**:
- `tech/Obsidian/插件`
- `tech/编程/Python`
- `tech/系统/架构`

### 一级分类：类型 (Type)

文档类型和形式分类。

**二级分类**:
- `type/报告` - 工作报告、分析报告
- `type/模板` - 文档模板、表单
- `type/指南` - 操作指南、教程
- `type/索引` - 索引目录、导航页
- `type/系统` - 系统设计、框架
- `type/会议` - 会议记录、纪要
- `type/计划` - 工作计划、规划

**常用标签**:
- `type/报告/绩效报告`
- `type/模板/工作模板`
- `type/指南/操作指南`
- `type/索引/知识索引`

### 一级分类：状态 (Status)

文档状态和属性。

**二级分类**:
- `status/进度` - 进度状态（草稿、进行中、已完成等）
- `status/优先级` - 优先级（紧急、高、中、低）
- `status/时间` - 时间周期（年度、季度、月度等）
  - `status/时间/2026-H1` - 2026上半年
  - `status/时间/2026-Q1` - 2026一季度
  - `status/时间/2026-Q2` - 2026二季度
  - `status/时间/2026-Q3` - 2026三季度
  - `status/时间/2026-04` - 2026年4月
  - `status/时间/2026-05` - 2026年5月
  - `status/时间/2026-06` - 2026年6月
  - `status/时间/2026-07` - 2026年7月
  - `status/时间/2026-08` - 2026年8月
- `status/版本` - 文档版本

**常用标签**:
- `status/进度/草稿`
- `status/进度/进行中`
- `status/进度/已完成`
- `status/进度/已归档`
- `status/优先级/紧急`
- `status/优先级/高`
- `status/时间/2026-Q1`
- `status/时间/2026-04`

### 一级分类：属性 (Attribute)

内容属性和特征。

**二级分类**:
- `attr/敏感` - 敏感信息、保密内容
- `attr/参考` - 参考资料、外部链接
- `attr/案例` - 案例分析、实例
- `attr/工具` - 工具使用、配置

## 📝 标签使用规范

### 1. 标签数量
- 每篇笔记建议使用3-8个标签
- 至少包含1个领域标签和1个类型标签
- 状态标签根据实际情况添加

### 2. 标签顺序
建议按以下顺序排列标签：
```
[领域标签], [类型标签], [状态标签], [属性标签]
```

**示例**:
```yaml
tags: [work/营销, type/报告, status/进度/已完成, status/时间/2026-Q1]
```

### 3. 新标签创建
创建新标签前请检查：
1. 是否已有类似标签
2. 是否符合层级结构
3. 是否会在其他笔记中复用

### 4. 标签维护
- 每月检查一次标签使用情况
- 合并意义相近的标签
- 删除不再使用的标签
- 更新标签文档

## 🔄 现有标签迁移指南

### 第一阶段：关键笔记迁移
1. 为[[知识管理/主页]]、[[工作/我的当前岗位]]等核心笔记添加层级标签
2. 更新工作相关笔记的标签
3. 更新AI/技术相关笔记的标签

### 第二阶段：批量迁移
1. 使用Dataview查询找出需要更新的笔记
2. 批量更新相似标签
3. 验证迁移效果

### 第三阶段：优化完善
1. 收集使用反馈
2. 调整标签结构
3. 更新规范文档

## 📊 标签统计与维护

### 月度维护任务
1. **标签使用分析**
   - 统计最常用标签
   - 识别冗余标签
   - 发现标签空白领域

2. **结构优化**
   - 调整不合理层级
   - 合并相似标签
   - 创建新分类

3. **文档更新**
   - 更新本规范
   - 更新标签索引
   - 发布变更通知

### 维护工具
- **Dataview查询**: 用于标签统计分析
- **Tag Wrangler插件**: 用于批量标签管理
- **自定义脚本**: 用于自动化迁移
